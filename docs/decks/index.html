Introduction: how to read this report

Each pipeline answers one question

Input

Material that enters a pipeline. Examples: article records, a gene list, or normalized identifiers.

Tool

Database or software that performs one step. Examples: PubMed, STRING, g:Profiler, or DAVID.

Filter

A rule that keeps or removes records. Filters reduce noise. They can also change results.

Output

A file or result from a pipeline. Outputs are evidence for follow-up. They are not final proof.

Terms used here. A candidate gene passes a research filter. A network edge is a reported protein association. An enriched term occurs more often than expected against a defined background.
Definitions follow the pipeline documentation in JOURNEY.md and DAVID pathway report.2 / 15

Literature review: purpose and input

Literature review asks what published evidence already exists

Purpose

Find articles that mention named pathways or processes. Link articles to controlled pathway names and historical HPO terms.

Input

Eight HPO identifiers, 53 pathway synonym rules, exact PubMed queries, eligibility rules, and a frozen article snapshot.

Tools

PubMed ESearch and EFetch retrieve metadata. PMC resolves full-text availability. Reactome and KEGG support pathway identifiers.

Output

Search log, article registry, scored article table, pathway evidence table, rankings, heatmap, and UpSet summary.

Scope limit. This repository contains documentation of the literature workflow. The described patch and frozen scored article table are not installed here.
Source: literature workflow reproduction.4 / 15

Literature review: workflow and filters

Article records move through retrieval, annotation, and review

SearchRun versioned Boolean queries. Record source, date, hit count, and query text.
RetrieveFetch metadata. Resolve available full text. Deduplicate records by PMID or DOI.
Annotate and mapMatch configured pathway and HPO terms. Assign checked Reactome or KEGG references.
Filter and aggregateKeep pathway mentions. Count distinct articles and HPO coverage by named pathway.

Important filters

  • Pathway inclusion needs a literal pathway or configured process phrase.
  • Gene-only mentions do not enter the pathway ranking.
  • The old 48-paper manual subset is not an eligibility filter.

Required human review

  • Screen titles, abstracts, and full text against prespecified rules.
  • Record exclusions and reviewer disagreements.
  • Use design-appropriate risk-of-bias assessment.

Phase 0–1: gene analysis

Gene analysis converts annotated VCF records into candidate seed genes

Input

18,252 annotated variant records from an upstream evidence table. Optional Exomiser files can add phenotype-ranking fields.

Tools

VEP and snpEff provide consequence annotation. gnomAD, ClinVar, CADD, SpliceAI, REVEL, and AlphaMissense supply supporting evidence.

Phase 0 output

A consolidated candidate-variant table. Each record stores gate status and a reason summary.

Phase 1 output

A gene mechanism matrix. A gene with one or more passing candidate variants becomes a network seed.

Plain-language purpose. This is a triage process. It keeps variants that are rare enough and damaging enough to justify research follow-up.
Source: JOURNEY.md, Phase 0 and Phase 1.7 / 15

Phase 0: gene analysis workflow and filters

Three gate types determine whether a variant becomes a candidate

Check coordinatesRequire a chromosome, positive position, reference allele, and alternate allele.
Check rarityKeep low-frequency or gnomAD-not-found alleles. Threshold: allele frequency ≤ 0.001.
Check impactKeep records that meet at least one functional or clinical evidence criterion.
Aggregate by geneGenes with one or more passing records become Phase 1 seed genes.

Impact criteria

High-impact consequence, P/LP ClinVar, CADD ≥ 20, SpliceAI ≥ 0.2, REVEL ≥ 0.5, or AlphaMissense ≥ 0.5.

Special handling

Unknown frequency can pass only in an MVA-context gene and only with an impact pass. Genes with two or more passing records receive a multi-hit flag.

Code and report differ. Narrative reports list NHOMALT < 5 as a rarity filter. Current code records population homozygotes but does not apply this threshold as a gate.
Gate implementation: candidate_consolidation.py. Reported thresholds: JOURNEY.md.8 / 15

Phase 2: network pipeline

The network pipeline asks whether candidate seed genes show protein associations

Input

1,985 Phase 1 seed genes. Each gene has one or more passing candidate variants.

Tools

g:Profiler g:Convert standardizes symbols. STRING v12.5 provides protein association data.

Network filter

STRING combined score must be at least 0.700. The query adds zero extra proteins. Only seed-gene associations remain.

Output

Seed-gene list, STRING edge table, network summary, component summary, node table, and two HTML network views.

Normalize symbolsMap input symbols to official HGNC symbols with g:Convert.
Query STRINGRequest associations at high confidence. Add no outside proteins.
Summarize graphCount edges and components. Identify components that contain MVA-related genes.

Pathway pipeline: methods and filters

Pathway analysis tests annotations against a stated gene background

Select genesUse candidate seed genes as the foreground. Choose a background gene universe.
Test annotationsUse Reactome, g:Profiler, or DAVID to test whether terms occur more often than expected.
Apply correctionUse the provider-adjusted value before interpreting an enrichment result.

Phase 2 pathway export

Reactome Analysis Service and g:Profiler use Phase 2 seed genes. The saved export has pathway names and FDR values.

Independent P0–P7

g:Profiler uses passing candidate genes as foreground and all evaluated Phase 1 genes as background. It retains BH-adjusted values.

DAVID addendum

DAVID uses normalized Ensembl identifiers and an uploaded custom background. It counts terms at Benjamini ≤ 0.05.

Filter rule. Do not mix FDR, BH q, EASE, or Benjamini values. These providers test different mapped identifiers, backgrounds, and term sets.

Conclusion and next steps

Use the pipelines to prioritize follow-up, not to make clinical conclusions

What the combined workflow provides

  • Published context for known MVA-related genes and processes.
  • A documented candidate seed-gene list from VCF evidence filters.
  • A strict, no-expansion STRING network context.
  • Three pathway-analysis views with explicit statistics and backgrounds.

What still requires validation

  • Variant confirmation and allele phase.
  • Cellular or functional evidence for a proposed mechanism.
  • Reconciliation of code, saved tables, and narrative counts.
  • Pathway analysis with a defensible callable-gene background.
Final conclusion. Literature, candidate-gene filtering, network context, and pathway analysis form a reproducible research workflow. The outputs generate hypotheses. They do not diagnose disease or demonstrate therapeutic benefit.
